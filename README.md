# لوحة حركة بوابات جامعة الزرقاء

واجهة React + TypeScript + Vite لعرض حركة الدخول والخروج من بوابات الجامعة. تحتاج إلى رابط خدمة ORDS مضبوط؛ لا تعرض بيانات اصطناعية عند غياب الرابط.

تُحدّث البيانات تلقائياً كل 5 دقائق، مع إمكانية التحديث اليدوي من زر التحديث في رأس اللوحة.
تُحفظ الأيام المعروضة مؤقتاً في ذاكرة الصفحة (حتى 3 أيام): اليوم الحالي لمدة دقيقة، والأيام المكتملة لمدة 15 دقيقة. لذلك تغيير نطاق التاريخ والعودة إليه أسرع، بينما زر التحديث اليدوي يجلب بيانات جديدة من ORDS.

تُزال القراءات المتقاربة لنفس الشخص والبوابة إذا وصلت خلال نافذة 60 ثانية، حتى لا تتضخم أرقام الحركات بسبب تكرار قارئ البوابة.

## التشغيل

```bash
npm install
npm run dev
```

لإنشاء ملفات APEX الثابتة:

```bash
npm run build
```

ستوجد الملفات النهائية في مجلد `dist`. إعداد Vite يستخدم مسارات نسبية حتى تعمل الملفات بعد رفعها كـ Static Files.
ارفع `index.html` **وجميع** الملفات داخل `dist/assets` مع الحفاظ على أسماء الملفات ومسار `assets/`. تُحمّل صفحات الرئيسية والبوابات والتسجيل ملفات JavaScript منفصلة عند فتح كل صفحة؛ رفع `main.js` و`main.css` وحدهما لن يكفي.

## ربط ORDS

انسخ `.env.example` إلى `.env.local` واضبط:

```env
VITE_ORDS_BASE_URL=/ords/zu_gates/gates-dashboard
```

تطلب الواجهة بيانات كل يوم من المسار السريع (حتى 31 يوماً للفترة المختارة، وبحد أقصى 3 طلبات متزامنة):

```text
GET {VITE_ORDS_BASE_URL}/transactions-day/?day=2026-10-26
```

يُحسب مؤشر الموجودين والرسوم المرتبطة به من خدمة مستقلة، وفق آخر حركة ناجحة لكل شخص خلال 24 ساعة قبل وقت نهاية الفترة (مع تضمين وردية الليل):

```text
GET {VITE_ORDS_BASE_URL}/presence-snapshot/?at_date=2026-11-01&at_time=12:00&lookback_hours=24
```

ثبّت `transactions_table/ords_presence_snapshot_handler.sql` في مخطط `ZU_GATES` قبل نشر الواجهة. فلاتر «من تاريخ/وقت» تخص الحركات؛ فلاتر «إلى تاريخ/وقت» تحدد لحظة احتساب الموجودين. المؤشر يعتمد على اكتمال تسجيل الدخول والخروج، ولا يحتسب آخر دخول أقدم من 24 ساعة.

تعود الاستجابة مصفوفة كاملة، وكل حركة فيها مصفوفة قصيرة بترتيب الحقول:

```text
[trans_id, employee_id, employee_name, tr_time, direction, gender,
 suffix, emp_position, center, dept_name, zone_name]
```

إذا لم يكن المسار السريع مثبتاً (HTTP 404)، تستخدم الواجهة المسار القديم المقسم إلى صفحات:

```text
GET {VITE_ORDS_BASE_URL}/transactions/?from_date=2026-09-28&to_date=2026-09-28
```

مثال استجابة المسار القديم ضمن `items`:

```json
{
  "items": [
    {
      "trans_id": 29355151,
      "employee_id": "12345",
      "employee_name": "Example User",
      "tr_date": 20260204,
      "tr_time": 74556,
      "trans_direction": "IN",
      "employee_gender": "1",
      "suffix": "2",
      "center": "مركز الحاسوب",
      "dept_name": "شعبة برمجة الحاسوب",
      "zone_name": "Bus_Park",
      "event_id": 1
    }
  ]
}
```

التحويلات المستخدمة:

- الجنس: `1` ذكر، `2` أنثى.
- الفئة: `1,5,6` طلاب، `2` إداريون، `3` أعضاء هيئة تدريس، وما عدا ذلك «أخرى».
- تعرض اللوحة الحركات الناجحة `EVENT_ID = 1` في المؤشرات والرسوم.
- تتحول قيمة `ZONE_NAME` إلى اسم البوابة العربي في `src/data/gateMapping.ts`.

ثبّت المسار السريع من `transactions_table/ords_dashboard_fast_handler.sql` في Schema ‏`ZU_GATES` بعد إنشاء الوحدة الموجودة في `transactions_table/ords_dashboard_module.sql`. المسار القديم احتياطي؛ تتبع الواجهة رابط `next` وتُظهر خطأ إذا تعذر جلب كل الصفحات بدلاً من عرض مجموع ناقص.

المشروع الحالي مضبوط على خدمة جامعة الزرقاء الفعلية. أثناء التطوير يمر الطلب عبر Vite proxy لتجنب CORS، بينما يستخدم Build مسار ORDS النسبي على نفس نطاق APEX.
